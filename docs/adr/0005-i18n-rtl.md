# ADR 0005 — i18n and RTL strategy

- Status: Accepted
- Date: 2026-05-13

## Decision

- Locales day one: `ar` (Arabic, RTL) and `en` (English, LTR).
- Locale routing: subpath (`/ar/...`, `/en/...`) on storefront and admin. POS is locale-switchable in app settings (no URL prefix).
- Default locale: `ar` for storefront (Egypt-first); `en` for admin.
- Catalogs live in `packages/i18n/src/catalogs/<locale>/<namespace>.json`. Type-safe keys generated from `en` as the canonical source.
- Translations are linted: `pnpm i18n:check` fails CI on missing keys or unused keys.

## RTL rules

- `<html dir="rtl" lang="ar">` for Arabic; mirror layout via CSS logical properties (`margin-inline-start`, `padding-block-end`, etc.) — no `ltr-only`/`rtl-only` overrides except where a glyph or icon must not mirror.
- Icons that have meaning (chevrons, arrows) are flipped by the `dir` attribute via Tailwind `rtl:` variants. Brand glyphs and product imagery are not flipped.
- Numbers: Western digits everywhere for prices and SKUs; Arabic-Indic digits only when explicitly opted into by user setting.
- Dates: `Intl.DateTimeFormat` with the `gregory` calendar; localized via `Intl.Locale`.
- Currency: `Intl.NumberFormat` with `currency: 'EGP'` default; user-switchable.

## Consequences

- All UI primitives in `packages/ui` are built with logical properties from the start; later RTL-retrofit is forbidden.
- Playwright fixtures parametrize on locale; every page test runs in both `ar` and `en`.
- Storybook has a global toolbar item to switch dir/locale, and the a11y addon runs against both.
